A figure is a result, and like any result it should be reproducible from the data and the code that produced it. Figures drawn by hand in a graphics program cannot be regenerated, and a correction to the data requires redrawing them, which invites error. Generating each figure by a script from a stated data file makes the figure a product of the analysis, so that every change to the data is reflected in every figure that depends on it.

The script should separate the data, the plotting code and the styling. The data are read from a file with a stated identifier, the plotting code transforms them into a figure, and the styling, such as colours, fonts and sizes, is set in one place. This separation makes it possible to change the appearance of all the figures together and to check that the data have not been altered in the process. Rougier et al. (2014) advised that a figure should be generated from its data, and Peng (2011) argued that the means of producing a result must accompany it.

The software versions and the random seeds that affect a figure should be recorded. A figure of a clustering, a simulation or a jittered plot depends on random choices, and a different seed gives a different figure. The versions of the plotting library and of the language determine default settings, which may change between releases and alter the appearance of a figure that is otherwise unchanged. Sandve et al. (2013) recommended recording these details so that a figure can be regenerated.

Figures should be exported in vector formats where possible, since these remain sharp at any size and allow the text and the lines to be inspected. The source data behind each figure should be deposited alongside it, so that a reader can recreate the plot and test an alternative display. A figure whose data are available can be checked for the distortions discussed in the previous chapter, and a figure whose source is not available cannot.
